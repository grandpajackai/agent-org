Notes on the system

Six AI agents, one per domain,
and the rules that keep them honest

I run a small portfolio of businesses — a trading system, client web work, a service business, a product — and I run a separate AI agent for each one. Not one assistant with a long prompt: six agents with separate memory, separate scheduled jobs and separate instructions. This page describes how it is put together and what I had to change once it was actually running.

Rules that turned out to matter

Own exactly one domain

Each agent stays inside its lane. When work belongs to another agent it says so and names which one, instead of improvising outside its context. Overlapping memory is how two agents quietly corrupt each other's state.

Shared memory is read-only

Every agent reads one plain-markdown knowledge vault. Exactly one profile - the orchestrator - is allowed to write to it. Nothing is locked; the discipline is the lock. A shared write surface with six writers is a race condition with extra steps.

Never fabricate

If a source is silent the agent writes not established in the sources and moves on. Numbers carry the date they were true. Assumptions are labelled as assumptions. A plausible-sounding invented figure is worse than a blank.

Contradictions get tabulated, not resolved

When two sources disagree the agent writes both down and marks it unresolved. Silently picking a winner produces a confident answer that is wrong for whoever reads it next.

Escalate only at hard walls

Passwords, phone codes, payments, someone's inbox. The agent logs the blocker, then keeps working on everything else. Nothing stops because one sub-task is stuck.

Alerts must be switchable off

A watchdog re-reporting a known condition gets muted, and muting it is how the real outage is missed. These ones report transitions, not standing state.

What is deliberately not on this page

  • Client names. Not my call to make. A client did not agree to appear in my marketing, so every business I build for is described by category and nothing else.
  • Any money. No revenue, no invoices, no targets, no P&L — in any form. Numbers without their dates are the easiest thing to misread.
  • Infrastructure detail. No registrars, expiries, addresses, hostnames or paths. Knowing where I keep things is a map of where to look.
  • Anything from the vault itself. This page is a generated summary sitting beside the knowledge base, not a window into it. The vault holds chat history, security notes and research on real people, and it is not published in any form.
